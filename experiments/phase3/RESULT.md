# Phase 3 验收记录

日期：2026-11-01。实现：Rust v0.3，10 个 crate。范围：持久化、恢复、上下文预算及 macOS CLI；没有在本阶段调用云端模型。

## 交付内容

- `agent-store::SessionJournal`：0600、单写者锁、version/seq 校验、每条同步持久化、半写尾部修复、全量状态重放。
- kernel：统一的临时/持久状态机、执行前意图、未知结果不重放、同批依赖调用关闭、旧审批失效、终止事件修复、最终回答缓存和同 thread 续做。
- `agent-context`：工具结果投影预算、保留完整用户指令的确定性摘录压缩、call/result 成对处理、压缩视图记录与重放、超限请求前拒绝。
- CLI：`--session`、`--resume`、`--context-tokens`、`--tool-output-bytes`；默认输出上限实际传递给 provider；绑定原步数上限且保留已消耗次数。

Phase 3 的 11 项 CLI 用例覆盖：

1. 完成后无额外模型调用的缓存恢复；同一 thread 后续任务保留助手历史；日志私有且不包含鉴权 key。
2. 审批等待时 SIGKILL，恢复使用新 approval ID，旧 ID 关闭，不额外采样原工具计划。
3. 命令已写标记但结果未落盘时 SIGKILL；恢复输出 unknown，标记只写一次，同批后续命令不执行。
4. 工具结果已落盘、模型仍等待时 SIGKILL；恢复不重跑工具，重新采样使用相同 history。
5. 取消后新 turn 续做；原工具 call/result 配对，未批准调用没有副作用。
6. 半条尾部修复；完整损坏记录拒绝，不发送模型请求。
7. 单写者锁；Running turn 禁止混入新 prompt，拒绝时不修改会话。
8. 网络/文件能力/命令白名单改变拒绝；工作区内的会话路径拒绝。
9. 连续十次大文件读取触发压缩；每次请求预算内、保留用户原文、工具配对；完整工具返回仍在 WAL。压缩后等待模型时 SIGKILL，再恢复使用相同视图，随后新任务继续复用历史。
10. 过大的固定用户消息在第一次 API 请求之前失败。
11. 模型等待时 SIGKILL 后步数仍消耗；恢复省略上限仍沿用原值，不重置预算。

大文件用例实测：每次工具返回 50000 UTF-8 bytes，10 次读取、2 次压缩；包含丢失响应重采样及后续任务共 13 次请求，最大本地估算量 9650，低于设置的 10000；每条工具投影不超过 2048 bytes。

Rust kernel 的两项新增测试另外枚举 planned / started / result / final / terminal 五个持久化位置，并模拟 unknown 写入后、同批剩余调用关闭前再次崩溃。store 测试覆盖损坏记录拒绝与非法转换不能写入日志。

## 结论与限制

确定性验收表明：该内核可以跨进程继续受监督的任务，保留历史，并在上下文增长时压缩请求视图。它不代表已经测得真实模型长任务成功率。

SIGKILL 可能留下仍运行的子进程；unknown 恢复不会自动重放，也不保证旧进程已经终止。当前仅有进程崩溃实验，没有断电可靠性验证。预算是本地保守估算，压缩为有损摘录；不包含厂商 tokenizer、语义摘要、多机恢复、加密、日志认证、快照索引或迁移工具。WAL 是事件权威记录，stdout 与普通事件文件不承诺事务式投递。

下一步：使用隔离工作区和外部验收测试，对真实模型运行跨中断、多轮修改与长上下文任务，统计恢复后的成功率和压缩造成的失败样本；再推进 Phase 4 的 Anthropic adapter。
