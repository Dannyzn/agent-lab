# 0003：追加式会话与可重建上下文

状态：已实现。日期：2026-11-01。范围：Rust v0.3，受监督的 macOS CLI。

## 问题

只有生命周期事件不能重建模型输入；只保存最近一次请求也会丢失被压缩的工具结果。另一个风险是：进程崩溃后，工具可能已经产生副作用，但宿主尚未保存结果。直接重放会重复写入或执行命令。

## 决策

1. 可选 `--session` 开启私有、追加式 WAL。每条记录包含 schema version、连续序号和中立运行时数据。所有影响恢复的记录在返回前 `sync_data`；工具执行意图必须先持久化，随后才执行副作用。公开事件也先写 WAL，再发送 stdout / 普通事件文件。
2. 单文件持有非阻塞 `flock`，创建不覆盖，权限 0600，拒绝最终路径的符号链接；会话文件必须位于工具工作区外。打开时只修剪末尾没有换行的半条记录；完整但损坏的 JSON、版本/序号异常和非法状态转换均拒绝。
3. `ModelReturned` 先保存整个标准化响应和全部待执行调用。尚未开始的调用重新走本进程审批；已经开始但没有持久化结果的调用记为 `execution_state=unknown`，不自动重放。同批后续调用记为未执行，由模型检查工作区后重新规划。该屏障可从 unknown 结果重建，恢复过程中再次崩溃也不会丢失。
4. canonical history 保留用户消息、助手消息和工具返回的完整结果；request history 是预算约束下的视图。工具本身已有的输出上限依然生效，因此“完整结果”不代表无限保留进程原始输出。
5. 上下文超限时使用确定性的摘录压缩：用户消息逐字保留，仅删除完整的 call/output 对，保留最近工具交互并添加有界历史摘录。摘录标注为不可信历史数据，不提升为 system 指令。完整历史与压缩视图都可恢复。
6. 持久化绑定工作区、沙箱、审批模式、命令白名单、模型调用步数上限和上下文配置。恢复不隐式扩大能力。模型/网关/凭据不写入会话配置；调用端重新提供连接配置。宿主不校验两次连接是否使用同一个模型。

## 取舍

- 无 journal 的运行使用同一个状态机，原有首个 contract 的事件顺序保持兼容。持久化是显式选择，避免一次性任务自动留存源代码与任务内容。
- append + replay 简单可审计，但没有快照索引；当前记录验证复制状态、重放全量日志，内存和耗时会随会话增长。后续依据长任务数据决定何时增加快照和分段。
- 不承诺外部副作用 exactly-once；unknown 是诚实的不确定性标记。SIGKILL 不触发取消清理，工具子进程可能继续运行；恢复不代表旧进程已经结束，必要时必须由操作员检查并终止。
- stdout 与 `--events` 不是事务投递。WAL 是权威记录；已写 WAL、尚未发送的事件可能不出现在外部流。持久化事件有稳定 `event_id`，宿主可读取 WAL 中 `event` 记录补齐并去重；普通流没有消费游标或自动全量重发。
- 本地预算按 JSON UTF-8 字节数加固定框架余量与输出预留估算，不是厂商 tokenizer；不保证覆盖网关添加的隐藏 prompt。摘录压缩会丢失细节，用户消息累计过大或压缩后仍超限则在请求前拒绝。
- 仅有进程崩溃/尾部半写的恢复测试，没有断电实验、加密存储、日志认证或 schema 迁移。日志应按源码与用户任务数据保护，不提交到 Git。
